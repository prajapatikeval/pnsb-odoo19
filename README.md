# PNSB Machinery Industries — Odoo 19 on Render

Odoo 19 with the `pnsb_website` addon: the company website of PNSB Machinery
Industries LLP (Home, About, Services, Industries, Products & Work, Contact),
built on standard Odoo apps. The catalogue is made of normal **Sales** products;
visitors build an enquiry list, and each enquiry becomes a draft **Sales
quotation** (or a **CRM** lead when it has no products), with drawings attached.

```
addons/pnsb_website/   the website module
docker/boot.py         boot manager (config, DB init, module sync, admin password)
Dockerfile             image based on the official odoo:19.0
render.yaml            Render blueprint (web service + PostgreSQL)
docker-compose.yml     local replica of the Render setup
```

## Deploy on Render

1. Push this repository to GitHub.
2. In Render, create (or sync) a **Blueprint** from the repository. It creates
   the `pnsb-odoo19` web service and the `pnsb-db` database.
3. First deploy takes about 3–5 minutes on the free plan (database
   initialisation + module install). While it runs, the site shows a
   "getting things ready" page and the health check already answers, so the
   deploy does not time out.
4. Log in at `/web/login` (or the **Log in** button in the site header):
   - login: `admin`
   - password: the `ADMIN_PASSWORD` value in the service's **Environment** tab.

Later deploys only upgrade `pnsb_website` when its code changed; otherwise the
container is serving again in about 10–20 seconds. Apps that the module depends
on (`sale_management`, `crm`) are installed automatically at boot the first time;
on the free plan that one-off install can take 20–40 minutes, during which the
"getting things ready" page is shown.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `ADMIN_PASSWORD` | Password of the `admin` user. Generated by Render; change it in the Environment tab and redeploy to apply. |
| `ADMIN_LOGIN` | Optional: rename the admin login (for example to an e-mail address). |
| `MASTER_PASSWORD` | Odoo master password. The public database manager is disabled. |
| `EXTRA_MODULES` | Odoo apps to install at boot, comma separated, e.g. `crm,sale_management`. |
| `RESET_DATABASE` | Set to `YES_DELETE_EVERYTHING` to wipe the database once and start fresh, then remove it. |
| `ODOO_WORKERS` | Leave at `0` on the free plan (threaded server, websockets work). |
| `DB_*`, `PORT` | Filled in by the blueprint. |

## Why the previous setup failed, and what changed

| Problem | Cause | Fix |
| --- | --- | --- |
| Timeouts when installing modules or creating databases | On the free plan (0.1 CPU) an install runs for minutes inside a web request; the proxy / health check gives up and Render restarts the container mid-transaction ("cursor already closed"). | Installs and upgrades run at boot, before Odoo serves traffic, with no request timeout. Add apps through `EXTRA_MODULES` instead of **Apps › Install**. |
| Deploys failing / restarting during start | The port stayed closed while the module was reinstalled on every boot. | A placeholder answers `/web/health` immediately; modules are only upgraded when their code changed. |
| Broken images / CSS after a restart | Render's disk is wiped on every deploy and restart, but Odoo stored files on disk. | Attachments are stored in PostgreSQL (`ir_attachment.location = db`); stale file records are cleaned once. |
| Database manager exposed with a committed master password | `list_db = True` and `admin_passwd` in git. | Config is generated at runtime from environment variables; the database manager is disabled; one database only. |

Creating additional databases is intentionally disabled: Render's PostgreSQL
service hosts this single database. To start over, use `RESET_DATABASE`.

## Good to know

- **Free plan limits:** the web service sleeps after 15 minutes without
  traffic (first request then takes ~30–60 s) and Render's free PostgreSQL
  expires 30 days after creation. Use a paid plan for production.
- **Enquiries:** website enquiries with products appear in **Sales ›
  Quotations** (origin "Website enquiry"); messages without products appear in
  **CRM**. Uploaded drawings are attached to the record.
- **Catalogue:** **Sales › Products › Website Products**. A product is listed
  when "Show on Website" is ticked in its **Website** tab; it is grouped by its
  product category (categories need "Show on Website" too). Prices are never
  shown. Photos come from PNSB's company profile.
- **Contact details:** company address and phone come from the company
  (Settings › Companies); the second phone and the WhatsApp number are on the
  website record (Website › Configuration › Websites).
- **E-mail:** configure an outgoing mail server (Settings › Technical ›
  Outgoing Mail Servers) to send quotations from Odoo.

## 3D and third-party code

The home page and inner pages render real-time 3D models of parts PNSB makes, using
[three.js](https://threejs.org) r160 (MIT licence), bundled in
`addons/pnsb_website/static/lib/three/` so the site never depends on a CDN. The Contact page
map uses [Leaflet](https://leafletjs.com) 1.9.4 (BSD-2, bundled in `static/lib/leaflet/`) with
© OpenStreetMap contributors tiles. Visitors without
WebGL, and the website editor, see photos instead.

## Run locally

```bash
docker compose up --build
```

Open http://localhost:10000 (admin password: `change-me-locally`).
